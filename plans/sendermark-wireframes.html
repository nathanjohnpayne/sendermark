Sendermark—wireframes for the Mac app, every screen and state

A first pass at the interface described in the PRD (projects/sendermark/prds/sendermark.md). Sendermark is a native Mac app with two surfaces: a main window (1180×760) and a menu-bar popover (360×400). Each screen is one source, drawn once per state in light and in dark appearance. Every frame has a stable anchor of the form #fx-<screen>-<state>-<light|dark>.

Nothing here is built. The PRD builds a command-line tool first and this app second; the review screen below is also the specification for what sendermark review prints and in what order.

How to read a frame.
· Chips above a frame name the canvas, the appearance (light or dark), and whether the frame is the proposed default for that screen or a state of it (empty, in progress, error, or a variant).
· Numbered badges 1 point at the annotation with that number in the legend under the screen. A tag such as PRD · Trust model names the PRD section the element implements.
· Sheets and dialogs are drawn over their parent screen, dimmed.
· Companies are real; logos load live. Paste a Logo.dev publishable key into the Logos control below and each company’s logo is fetched from Logo.dev’s image CDN, the way the app’s own previews would fetch it. The key is kept in this browser and never written into the file. Without it, each company shows a neutral tile with initials. Sender numbers and message text are invented.
· Zoom (control below) scales the window canvas; the popover is 1:1 by default.

Visual system—tokens, type and the sender-type palette

A quiet Mac utility: a white Window, a cool grey Sidebar, Ink text, Graphite for secondary text, and one accent—Stamp, an ink-pad indigo—for the selected sidebar item, the primary button, and selection. Type is the system font throughout. Sender handles are set in the system monospace, because approving a number means checking it digit by digit. Colour is reserved for the one thing that changes what you should do: the type of sender. Each type has its own hue, icon and label, and the three are never separated, so the type survives a greyscale screenshot.

Contrast is computed, not guessed—the ratios below are calculated at page load from the hex values (WCAG 2.x relative luminance).

Dark appearance

The same roles with their own values, not an inversion. The window drops to a near-black grey and sheets, buttons and the popover sit one step lighter, so elevation reads without shadows. Stamp splits in two: a slightly lighter fill for buttons and selection, and a pale violet for links and icons, because the light-mode indigo fails as text on a dark window. Each sender type keeps its hue and swaps a pale tint for a deep one. Company logos are not recoloured: a logo with a white tile stays white, as a contact photo does.
